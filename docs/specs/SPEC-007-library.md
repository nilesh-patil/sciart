# SPEC-007: The `sciart` library

**Crate**: `crates/sciart` (lib target) · **Milestone**: M25 · **Status**: In progress · **ADR**: [0032](../adr/0032-library-facade.md)

The `sciart` crate is a library as well as a binary. Its library is a small facade: run a
scene without a terminal, list the scenes, turn a frame into text, ANSI or a PNG, and embed
a scene in a ratatui application. It is the only crate with a stability promise; the crates
behind it are internal.

- **LIB-R1** Surface: the library exposes exactly `scenes`, `find`, `SceneInfo`, `Category`, `Theme`, `Options`, `Stage` and `Error`; `SceneWidget` with the feature `widget`; and the module `experimental` with the feature `unstable-generator`. Each of these is defined in the facade; nothing from an internal crate is re-exported outside `experimental`. Deliberately absent: `Generator`, `Canvas`, `Ctx`, the painter, the HUD, the runtime, the config, the CLI, keep-awake and the art metrics. The art metrics move to `crates/sciart-qa` (`publish = false`, a dev-dependency). `crates/sciart/tests/lib_surface.rs` lists every public item of the facade into a reviewed snapshot and fails on a `pub use sciart_` outside `experimental`.
- **LIB-R2** No dependency types: no type from `rand`, `rand_chacha`, `ratatui`, `crossterm` or `clap` appears in a public signature, except `ratatui` types in `src/widget.rs`, which compiles only with `widget`. `lib_surface.rs` rejects those paths in every other facade file.
- **LIB-R3** Room to grow: every public enum is `#[non_exhaustive]`; every public struct has private fields and is built through constructors or builder methods; the stable surface has no trait for users to implement. `experimental` re-exports `Generator` and its companion types and adds `Stage::from_generator`, with no semver promise, and its docs say so. `lib_surface.rs` checks the attributes and the absence of public fields; a doctest implements a `Generator` under `unstable-generator`.
- **LIB-R4** Features: `default = ["cli", "record"]`, so `cargo install sciart` gives the full binary (CLI-R15); the binary target has `required-features = ["cli"]`. A library user sets `default-features = false` and adds `png` and/or `widget`. With no default features the normal dependency tree has no `clap`, `anyhow`, `toml`, `serde`, `gif` or `sciart-keepawake`. docs.rs builds with `png`, `widget` and `unstable-generator`, never `mouse`. `scripts/tooling_check.py` resolves `cargo tree -p sciart --no-default-features -e normal` and asserts that the gate builds and lints the `--no-default-features` and `png,widget` combinations.
- **LIB-R5** Behaviour: `Options::default()` is seed 42, Unicode glyphs, title on. A size is clamped to at least 1×1. `Stage::advance(seconds)` takes fixed steps of 1/60 s until `floor(60 · total + 1e-6)` steps have been taken in all, so `advance(1.0)` equals sixty calls of `advance(1/60)`. The same build, scene, seed, size and call sequence give byte-identical text, ANSI and PNG output (per platform, ADR-0029). `to_ansi` produces the bytes `sciart frame` prints and `sciart record --format asciicast` embeds for the same frame: there is one ANSI writer. `SceneWidget` resizes its stage to the area it is given and writes the theme's exact colours only inside that area (tested through ratatui's `TestBackend`).
- **LIB-R6** Panics: when the crate is built with unwinding, a panic inside a scene during `advance` or a render becomes `Error::ScenePanicked`; the stage then stays failed, later calls return the same error and the widget draws nothing. Built with `panic = "abort"` the process aborts, and the crate docs and each `# Panics` section say so. The library never installs a panic hook and never touches the terminal: a source rule rejects `set_hook`, `enable_raw_mode` and the alternate screen in facade files.
- **LIB-R7** Documentation: the library has `#![deny(missing_docs, rustdoc::broken_intra_doc_links)]`; the crate docs carry runnable examples for headless stepping, listing scenes, ANSI, PNG and the widget; `examples/headless.rs` and `examples/widget.rs` exist. The gate runs `cargo test -p sciart --doc --features png,widget,unstable-generator`, and `scripts/tooling_check.py` asserts that it does.
- **LIB-R8** Pinned surface: the LIB-R1 snapshot changes only after a person has reviewed the diff, as TEST-R2 requires for scene snapshots. From the first release after 1.0.0, hosted CI also runs cargo-semver-checks against the published 1.0.0; it is installed in CI only and stays out of `rs-ci`. `scripts/tooling_check.py` asserts the workflow step exists.
