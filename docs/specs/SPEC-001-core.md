# SPEC-001: sciart-core

**Crate**: `crates/sciart-core` · **Milestones**: M1, M4–M7, M10–M12 · **Status**: Implemented (CORE-R1..R77; R60..R70 from the post-M10 audit, R71..R77 in M11); CORE-R78..R96 in M12

Pure, terminal-agnostic primitives. No I/O, no OS calls, no global state.

## Requirements

### Size
- **CORE-R1** `Size::new(w, h)` clamps both dimensions to `>= 1`. `Size::area()` returns `w*h` as `usize`.

### Glyph & Canvas
- **CORE-R2** `Canvas::new(size, mode)` allocates exactly `width*height` cells, all blank (`' '`, `Ink::BLANK`).
- **CORE-R3** `Canvas::put(x, y, glyph, ink)` with `x`/`y` outside the canvas (including negative `i32`) is a silent no-op — never panics.
- **CORE-R4** `GlyphMode::Ascii` stores `glyph.ascii`; `GlyphMode::Unicode` stores `glyph.unicode` unless its display width ≠ 1, in which case it stores `glyph.ascii`.
- **CORE-R5** `Canvas::resize(size)` reallocates only when the size changes, and leaves a fully blank canvas. `Canvas::clear()` blanks all cells without reallocating.
- **CORE-R6** `Canvas::to_lines()` returns exactly `height` strings, each exactly `width` chars (used by snapshot tests and `--ascii` debugging).
- **CORE-R7** `Canvas::get(x, y)` returns `Option<&Cell>`.

### Ink
- **CORE-R8** `Ink { role: Role, level: u8 }`; `Ink::BLANK` is `Role::Background` level 0. `Role` is a closed `#[non_exhaustive]` enum of semantic roles; generators must not encode RGB.

### Fixed-step clock
- **CORE-R9** `FixedStep::new(dt, max_steps)`; `advance(elapsed_secs) -> u32` adds `elapsed` to an accumulator and returns `floor(acc / dt)` steps, keeping the remainder.
- **CORE-R10** When more than `max_steps` steps are due, `advance` returns `max_steps` and discards the excess accumulator (no spiral of death).
- **CORE-R11** Negative or non-finite `elapsed` is treated as 0.
- **CORE-R12** `alpha()` returns `acc / dt` in `[0, 1)` for optional interpolation.

### Context & RNG
- **CORE-R13** `Ctx::new(seed, size)` owns a `ChaCha8Rng` seeded from `seed`, the current `Size`, and `time` (simulated seconds, advanced only by the runtime via `Ctx::advance(dt)`). Same seed + same call sequence ⇒ identical RNG output.

### Generator trait
- **CORE-R14** Trait (object-safe, `Send`):
  `meta() -> &'static Meta`, `resize(Size, &mut Ctx)`, `update(f64, &mut Ctx)`, `render(&self, &mut Canvas)`, and (M11) `caption(&self) -> Option<&'static str>` with a default body (CORE-R71).
  `Meta { name: &'static str, category: Category, description: &'static str, title: &'static str, captions: &'static [&'static str] }` (CORE-R71, CORE-R77).
- **CORE-R15** Call protocol guaranteed by callers: `resize` before the first `update`/`render`, and again whenever size changes; `render` receives a cleared canvas of the same size last passed to `resize`.

### Geometry helpers
- **CORE-R16** `geom::ASPECT = 2.0`; `geom::polar(cx, cy, r, theta) -> (i32, i32)` applies `ASPECT` to x.
- **CORE-R17** `geom::line(x0, y0, x1, y1)` yields Bresenham points inclusive of both endpoints.
- **CORE-R18** `geom::wrap(v, max)` returns `v` modulo `max` in `[0, max)` for floats, for any finite `v` and `max > 0`.

### Stage (the single implementation of the call protocol)
- **CORE-R19** `Stage::new(generator, seed, size, mode)` builds a `Ctx`, calls `resize` once, and owns a front and back `Canvas`. `Stage::resize(size)` forwards to the generator only when the size changes.
- **CORE-R20** `Stage::step(dt)` calls `update(dt)` then `ctx.advance(dt)`.
- **CORE-R21** `Stage::render()` clears the back canvas, lets the generator draw into it, then swaps it to the front. If the generator panics mid-render, `Stage::frame()` still returns the previous complete frame (supports RT-R3).

### Drawing helpers (`draw`, M4)
All take centers/radii in **rows** (x is stretched by `geom::ASPECT`), clip to the canvas, never panic for any finite or non-finite input, and cost time proportional to the *visible* area they touch.
- **CORE-R22** `draw::orbit(canvas, cx, cy, r, glyph, ink)` draws a closed ellipse outline of radius `r` rows: every drawn cell lies within 1 cell of the ideal curve, and consecutive samples are dense enough that the outline has no gaps (adjacent drawn cells are 8-connected). `r <= 0` draws nothing.
- **CORE-R23** `draw::disc(canvas, cx, cy, r, shader)` visits every cell whose aspect-corrected normalized distance `d = dist / r` is `<= 1`, calling `shader(d, nx, ny) -> Option<(Glyph, Ink)>` with `nx, ny ∈ [-1, 1]` the normalized offsets; `None` leaves the cell untouched. With `0 < r < 0.5` only the center cell is shaded (with `d = 0`); `r <= 0` or non-finite draws nothing.
- **CORE-R24** `draw::field(canvas, shader)` calls `shader(x, y) -> Option<(Glyph, Ink)>` exactly once per cell.
- **CORE-R25** `draw::ramp(v, glyphs)` maps `v ∈ [0, 1]` onto `glyphs` (0 ⇒ first, 1 ⇒ last), clamping outside values; NaN ⇒ first. Panics only for an empty slice (a programming error caught by tests).
- **CORE-R26** `draw::text_centered(canvas, y, s, ink)` writes `s` horizontally centered on row `y`, clipped at both edges.
- **CORE-R27** `draw::fit_radius(size, frac)` is the largest radius in rows such that a circle of that radius (aspect-stretched) centered on the canvas fits within `frac` of both dimensions: `frac * min(width / (2·ASPECT), height / 2)`, never negative.

### Particle helpers (`particles`, M5)
Shared by the particle-system scenes. Pure, allocation-free after construction, deterministic given `ctx.rng`.
- **CORE-R28** `ParticlePool<P>::with_capacity(n)` holds at most `n` particles. `spawn(p) -> bool` adds `p` and returns `true`, or returns `false` and drops `p` when full. `retain(|&mut P| -> bool)` updates every particle in place and removes those for which the closure returns `false` (order is not preserved). `len`, `is_empty`, `capacity`, `iter`, `iter_mut`, `clear`, and `set_capacity(n)` (truncates when shrinking) complete the API. `ParticlePool::default()` is an empty pool of capacity 0 and allocates nothing (the placeholder until a scene sizes it with `set_capacity`). No operation other than `set_capacity` growing may allocate — verified with a counting allocator in `crates/sciart-core/tests/alloc_free.rs` (ADR-0009), as are CORE-R29 `push` and CORE-R36 `step` after its first call.
- **CORE-R29** `Trail<T: Copy>::new(n)` is a fixed-length history: `push(v)` appends and evicts the oldest when `n` entries exist; `iter()` yields oldest → newest; `len() <= n`; `n = 0` keeps nothing; `clear()` empties it.
- **CORE-R30** `gaussian(rng, mean, sd) -> f64` draws a normal variate (Box–Muller or `rand_distr`-free equivalent); always finite; `sd == 0` returns exactly `mean`; a large seeded sample has mean within 3 % of `sd` of `mean` and standard deviation within 3 % of `sd`; non-finite parameters are treated as 0 and a negative `sd` as `|sd|`. `gaussian2(rng, sd) -> (f64, f64)` draws an isotropic 2-D pair.
- **CORE-R31** `kepler_speed(gm, r) = √(gm / r)` and `kepler_omega(gm, r) = √(gm / r³)` for `r > 0`, `gm ≥ 0`; `0` for `r ≤ 0` or non-finite input (never NaN or ∞).
- **CORE-R32** `plot(canvas, x, y, glyph, ink)` takes **f64** cell coordinates, rounds to the nearest cell and ignores non-finite or off-canvas points (so particle code never casts NaN to `i32`).

### Grid helpers (`grid`, M6)
A dense 2-D field for automata, lattices and PDEs. Coordinates are `i32` cells `(x, y)`, row-major storage.
- **CORE-R33** `Grid<T: Clone>::new(size, fill)`; `size()`, `width()`, `height()`; `get(x, y) -> Option<&T>`, `get_mut`, `set(x, y, v) -> bool` return `None`/`false` off-grid (never panic for any `i32`); `fill(v)`; `iter()` yields `((x, y), &T)` in row-major order; `as_slice()` exposes the row-major buffer. A 0×0 grid (`Grid::default()`, since `Size` is at least 1×1) is valid and empty; use `width()`/`height()`/`is_empty()` for it. There is no panicking `Index` impl (GEN-R4); off-grid centres have no neighbours.
- **CORE-R34** `resize(size, fill)` keeps the values of cells whose coordinates exist in both sizes and sets new cells to `fill` (reusing the allocation when it is large enough).
- **CORE-R35** `neighbors(x, y, hood, edges)` iterates the in-grid neighbour coordinates of `(x, y)` (excluding itself) for `Hood::VonNeumann` (4) or `Hood::Moore` (8), with `Edges::Clip` (drop off-grid) or `Edges::Wrap` (toroidal; on a 1-wide or 1-tall grid a wrapped neighbour may equal the cell itself and is then skipped, and duplicates are yielded once). It does not allocate.
- **CORE-R36** `step(&mut self, scratch: &mut Grid<T>, rule)` performs one synchronous update: `scratch[x,y] = rule(&self, x, y)` for every cell, then swaps the buffers, so a rule never sees partially updated state. `scratch` is resized to match if needed and is otherwise not allocated.

### Integrator & timeline helpers (`ode`, `timeline`, M7)
For deterministic physics and scripted, looping narratives. Pure, allocation-free.
- **CORE-R37** `ode::rk4_step(y: &mut [f64; N], t, h, f)` advances `y' = f(t, y)` (with `f(t, &[f64; N]) -> [f64; N]`) by one classical 4th-order Runge–Kutta step; `ode::integrate(y, t, dt, h_max, f)` covers `dt` with `ceil(dt / h_max)` equal steps (none for `dt ≤ 0` or non-finite `dt`; `h_max` clamped to `MIN_STEP = 1e-6` and the step count capped at `MAX_STEPS = 4096` to protect GEN-R8; returns the step count). RK4 is exact for solutions that are polynomials of degree ≤ 4 in t. Global error on `y' = −y` over 1 s is `O(h⁴)` (halving `h` reduces it ≥ 12×); non-finite results are left for the caller to detect.
- **CORE-R38** `Timeline::new(&[(label, seconds)])` is a looping sequence of phases (non-positive durations are treated as zero-length and skipped); `at(t) -> Beat { index, label, local, progress }` with `local ∈ [0, duration)`, `progress = local / duration ∈ [0, 1)`, wrapping at the total length (any finite `t`, including negative, maps into the cycle); `total()`; `cycle(t)` returns the completed-cycle count. An empty or all-zero timeline returns index 0 with progress 0 and never panics.
- **CORE-R39** easing: `ease::smoothstep(x)`, `ease::in_out_cubic(x)`, `ease::out_quad(x)` map `[0, 1] → [0, 1]` monotonically with `f(0) = 0`, `f(1) = 1`, clamping inputs outside the range (NaN ⇒ 0); `ease::lerp(a, b, t)`.

### Raster, fields, symplectic & 3-D helpers (M10)
Sub-cell rendering (ADR-0010), colormap roles (ADR-0011), capped/resampled lattices (ADR-0012). Pure, deterministic, allocation-free after construction/resize.
- **CORE-R40** `Cell` gains `bg: Ink` (`Cell::BLANK.bg == Ink::BLANK`, meaning "no background"). `Canvas::put` resets `bg` to `Ink::BLANK`; `Canvas::put_bg(x, y, glyph, fg, bg)` sets both, with the same bounds and glyph-mode rules as `put` (CORE-R3, CORE-R4). `to_lines` is unchanged.
- **CORE-R41** `raster::Dots::new(cells: Size)` is a braille lattice of `2·w × 4·h` dots (`dot_size()`). `set(x: i32, y: i32, ink)` lights a dot; `plot(x: f64, y: f64, ink)` rounds and ignores non-finite points; off-lattice dots are no-ops. Each cell keeps the ink of its most intense lit dot (ties: last set wins), where intensity is `level`, except for `Role::Div`, where it is `|level − 128|` (a negative lobe keeps its strongest dot). `clear()`, `resize(cells)` (reallocates only when the size changes), `is_lit(x, y)`. `blit(&self, canvas)` writes every cell that has ≥ 1 lit dot as the braille glyph `U+2800 + mask` (standard dot order: bits 0–2 left column rows 0–2, bits 3–5 right column rows 0–2, bit 6 left row 3, bit 7 right row 3). Its ASCII fallback is by dot count: 1 ⇒ `.`, 2 ⇒ `:`, 3–4 ⇒ `+`, ≥ 5 ⇒ `#`. Cells with no lit dots are left untouched, so `Dots` layers over other drawing. `set`, `plot`, `clear` and `blit` never allocate.
- **CORE-R42** `raster::Pixels::new(cells: Size)` is a `w × 2·h` buffer of `Ink` (`Ink::BLANK` = empty), with square pixels at `ASPECT = 2`. It provides `set(x, y, ink)`, `get(x, y) -> Option<Ink>`, `fill`, `clear`, `resize(cells)` and `pixel_size()`. `blit(&self, canvas, ascii)`: in Unicode mode, both pixels empty ⇒ untouched; only top ⇒ `▀` fg top; only bottom ⇒ `▄` fg bottom; both ⇒ `▀` with fg top and bg bottom (`put_bg`). In ASCII mode it calls `ascii(x, y, top, bottom) -> Option<(char, Ink)>` per cell and writes the result, so every half-block scene has to supply its own fallback (GEN-R10). `raster::half_block(canvas, x, y, top, bottom)` is that Unicode cell rule for one cell, and `blit` draws every cell through it, so a scene that composites an overlay over a blitted buffer uses the same rule. Neither allocates.
- **CORE-R43** `grid::resample_bilinear(src: &Grid<f32>, dst: &mut Grid<f32>)` fills `dst` (keeping its size) by cell-centre-aligned bilinear sampling of `src` with edge clamping. It is identity for equal sizes, preserves constants exactly and preserves linear ramps in the interior. `grid::resample_nearest<T: Clone>(src, dst)` does the same with nearest-neighbour sampling, so only values present in `src` appear in `dst`. Both are no-ops on an empty `src` or `dst` and do not allocate.
- **CORE-R44** `ode::verlet_step(pos: &mut [f64], vel: &mut [f64], acc: &mut [f64], h, accel)` performs one kick–drift–kick leapfrog step, where `accel(pos, acc_out)` writes accelerations and `acc` must hold `a(pos)` on entry (it holds `a(pos')` on exit). Mismatched slice lengths make it a no-op. `ode::verlet_integrate(pos, vel, acc, dt, h_max, accel) -> usize` covers `dt` with equal substeps under the same count rules as `integrate` (CORE-R37: `MIN_STEP`, `MAX_STEPS`, no steps for `dt ≤ 0` or non-finite). Properties: exact for constant acceleration; time-reversible (step with `h`, negate `vel`, step again ⇒ start within 1e-12 relative); for the harmonic oscillator the energy error stays bounded (no secular drift) over 10⁴ periods at `h = T/50`. It does not allocate.
- **CORE-R45** `geom::Camera { yaw, pitch, distance }` (radians; `distance = f64::INFINITY` ⇒ orthographic). `project(&self, p: [f64; 3], centre: (f64, f64), scale: f64) -> Option<(f64, f64, f64)>` rotates `p` by yaw (about y) then pitch (about x) and returns screen `(x, y)` in cell units, with x stretched by `ASPECT`, y pointing down, `scale` in rows per world unit and perspective factor `d / (d − z)`. It also returns `depth = z` (larger = nearer). It returns `None` for non-finite input or points at or behind the eye (`z ≥ distance − 1e-9`). The origin maps to `centre`; `yaw = π/2` maps +x onto the depth axis.
- **CORE-R46** `Role` gains `Seq` (sequential field: level 0 = low, 255 = high) and `Div` (signed field: level 128 = zero, 0 = most negative, 255 = most positive) (ADR-0011). `ink::seq(v)` maps `v ∈ [0, 1]` and `ink::div(v)` maps `v ∈ [−1, 1]` onto those levels (clamped, NaN ⇒ low/zero).
- ~~CORE-R47~~ Superseded by CORE-R77 (M11): the `Category` enum is redefined, and `Basic` and `PhysicsChemistry` are removed.
- **CORE-R48** `grid::lattice_for(display: Size, max_nodes: usize, bucket: f64) -> Size` picks a capped simulation lattice for a display region in square units (ADR-0012). The aspect `display.w / display.h` is quantised to the nearest power of `bucket` (`bucket > 1`, for example `1.25`; otherwise treated as exact). It returns the largest lattice with that aspect and `w·h ≤ max_nodes`, never larger than `display` in either dimension, at least 1×1, and never panicking for any input (`max_nodes = 0` ⇒ 1×1). Two displays in the same aspect bucket whose sizes are both at or above the cap map to the same lattice, so resizing within a bucket does not touch simulation state.

### Shared scene helpers (M10, from the spec critics)
Each was requested independently by several M10 scene authors. They are pure, deterministic, allocation-free after construction/resize, and never panic for any input.
- **CORE-R49** `text::StackText<const N: usize>` is a fixed-capacity UTF-8 buffer implementing `core::fmt::Write`. It truncates silently at `N` bytes on a char boundary and provides `as_str()`, `clear()` and `len()`, and it never allocates, so `write!(buf, "T/Tc {:.2}", t)` is safe in `render` (GEN-R11). `draw::text_mode(canvas, x, y, unicode: &str, ascii: &str, ink) -> i32` writes `unicode` or `ascii` depending on the canvas glyph mode (left-aligned, clipped) and returns the column after the last char.
- **CORE-R50** `Camera::projector(&self) -> Projector` caches the yaw/pitch sines and cosines. `Projector::rotate(p) -> [f64; 3]` returns camera-space coordinates, and `Projector::project(p, centre, scale)` returns results bit-identical to `Camera::project`.
- **CORE-R51** `Dots::line(x0, y0, x1, y1, ink)` (f64 dot coordinates, rounded) lights a Bresenham segment on the dot lattice with both endpoints inclusive and clipped to the lattice. Non-finite endpoints draw nothing, and the length is capped (≤ 4·(dot width + dot height) dots) so wild coordinates stay cheap.
- **CORE-R52** `grid::SampleMap::rebuild(src: Size, dst: Size)` builds per-axis source-index and weight tables using the same cell-centre, edge-clamp convention as `resample_bilinear` (CORE-R43), and allocates only when it grows. `sample(&self, src: &Grid<f32>, x, y) -> f32` returns the bilinear value at destination cell `(x, y)` (identical to `resample_bilinear`'s output for that cell). `nearest(x, y) -> (i32, i32)` returns the nearest source cell. Off-range destination coordinates are clamped.
- **CORE-R53** `grid::laplacian9(src: &Grid<f32>, dst: &mut Grid<f32>, edges)` writes the isotropic 9-point Laplacian `(4·(N+S+E+W) + (NE+NW+SE+SW) − 20·c) / 6` (unit grid spacing). `Edges::Wrap` is periodic, and `Edges::Clip` is zero-flux (Neumann, ghost cells mirror the edge). Mirror pairs are summed first (`(W+E)`, `(N+S)`, …), so a left-right mirrored input gives a bitwise mirrored output. A constant field gives exactly 0, and on a periodic grid `Σ dst = 0` within rounding. `dst` is resized to `src` if needed.
- **CORE-R54** `particles::SpatialHash::new(width, height, cell)` is a uniform cell list over `[0, width) × [0, height)` built by counting sort. `rebuild(points: &[[f64; 2]])` keeps a stable index order within a bucket and clamps out-of-range or non-finite points to the border bucket. `for_each_within(p, r, |i| ..)` visits every index whose point lies within distance `r` of `p` (and possibly others from the overlapped buckets), each exactly once, in deterministic order. It allocates only when the point count or bucket count grows.
- **CORE-R55** `raster::Density::new(cells: Size)` is an `f32` long-exposure buffer at `Dots` resolution. It provides `decay(k)` (multiply all by `k ∈ [0, 1]`), `deposit(x, y, w)` (f64 dot coordinates, nearest dot, non-finite ignored), `get(x, y)`, `resize`, `clear`, and `to_dots(&self, dots, threshold, map: impl Fn(f32) -> Ink)`, which lights every dot whose value is `≥ threshold` with `map(value)` in one pass.
- **CORE-R56** `ink::soft_clip(x)` is the Padé tanh `x(27 + x²)/(27 + 9x²)`, clamped to `[−1, 1]`: monotone, odd, exactly ±1 at |x| ≥ 3, libm-free, NaN ⇒ 0. `ink::seq_value(Ink) -> f64` and `ink::div_value(Ink) -> f64` are exact inverses of `ink::seq`/`ink::div` on their levels, so `ink::seq(ink::seq_value(i)) == i` and likewise for `div`.
- **CORE-R57** `rng::SplitMix64` is a tiny deterministic generator for hot inner loops, seeded from `ctx.rng` so GEN-R7 still holds. It provides `new(seed)`, `from_rng(&mut impl Rng)`, `next_u64()` (reference: seed 0 ⇒ first output `0xE220A8397B1DCDAF`), `next_f64() ∈ [0, 1)` with 53 random bits, and `below(n: u32)`.
- **CORE-R58** `particles::InverseCdf<const K: usize>::build(a, b, density: impl Fn(f64) -> f64)` tabulates a non-negative density on `[a, b]` into `K` quantiles, with no allocation. `sample(u)` is monotone non-decreasing in `u ∈ [0, 1]` and lies in `[a, b]`, and it is exact for a uniform density (`a + u·(b − a)`). A density that is zero or non-finite everywhere falls back to uniform.
- **CORE-R59** `ode::tridiag_solve(sub, diag, sup, rhs, scratch) -> bool` solves a tridiagonal system in place into `rhs` (Thomas algorithm, `scratch` of the same length). Mismatched lengths or a zero pivot return `false`, leave `rhs` unchanged and never panic.

### Helpers lifted from the M10 scenes (post-M10 audit)

Each replaces code that two or more scenes had written for themselves. The scenes now call these, bit-identically unless the scene's SPEC-002 section says otherwise.

- **CORE-R60** `geom::v3` works on plain `[f64; 3]` (`type V3`): `add`, `sub`, `scale(a, k)`, `axpy(k, a, b) = k·a + b`, `dot`, `cross` (right-handed), `norm` and `unit` (`a / |a|`; the zero vector gives NaN). Each is the plain component-wise formula, so `cross(b, a) == −cross(a, b)` exactly and `cross(a, b)` is orthogonal to both within rounding.
- **CORE-R61** `geom::wrap_angle(a) = wrap(a + π, 2π) − π` wraps an angle into `[−π, π)` (NaN for non-finite input), for signed turns between headings.
- **CORE-R62** `geom::stroked_line(x0, y0, x1, y1, f)` walks the `geom::line` Bresenham cells and calls `f(k, x, y, (dx, dy))` with the cell index along the line and the step into the cell. The first cell takes its outgoing step, and a lone cell gets `(0, 1)`. `draw::step_glyph(dx, dy)` is the default glyph for a step: `─` with no vertical move, `│` for a vertical-only step, `╲` when `dx` and `dy` have the same sign and `╱` otherwise, with ASCII fallbacks `-`, `|`, `\` and `/`.
- **CORE-R63** `Projector::magnification(depth)` is the perspective factor `d / (d − depth)` that `project` scales a point by, and exactly 1 for an orthographic view. `draw::disc_covers(cx, cy, r, x, y) -> bool` is true exactly for the cells `draw::disc` visits on a canvas large enough to hold the disc (`d ≤ 1`, or only the rounded centre cell when `r < 0.5`), and false for input `disc` ignores (non-finite, `r ≤ 0`). `disc` uses the same inside test.
- **CORE-R64** `Dots::from_cells(x, y) -> (f64, f64)` maps continuous cell coordinates (cell `i` spans `[i, i + 1)`) to dot coordinates `(x·CELL_W − ½, y·CELL_H − ½)`, so `plot` of a point strictly inside a cell lights a dot of that cell. `Dots::cell_mask(cx, cy) -> Option<u8>` returns a cell's braille dot mask (CORE-R41 bit order), or `None` off the region.
- **CORE-R65** `Pixels::shade(&mut self, f: impl FnMut(i32, i32) -> Ink)` sets every pixel `(x, y)` of the `w × 2·h` buffer to `f(x, y)`, row by row, without allocating.
- **CORE-R66** `ink::level(v: f64) -> u8` rounds to the nearest level and clamps to `0..=255` (NaN ⇒ 0). `ink::MIN_VISIBLE_LEVEL = 12.0` is the level below which a scene should not draw: every theme keeps level 0 visible, so a fade ends by removing ink, not by dimming it to nothing.
- **CORE-R67** `draw::label(canvas, x, y, s, ink) -> i32` writes a blank cell (`Ink::BLANK`) at `x`, `s` from `x + 1`, and a blank cell after its last char (chars counted, not bytes), clipped at the canvas edge. It returns the column after the trailing blank.
- **CORE-R68** `grid::regrid_bilinear(field: &mut Grid<f32>, size, scratch)` and `grid::regrid_nearest<T: Clone>(field, size, scratch)` carry a field onto a new lattice (ADR-0012). They reshape `scratch` to `size` without preserving its contents (reusing its buffer), fill it by `resample_bilinear`/`resample_nearest` of `field`, and swap, so `field` becomes the resampled grid and `scratch` holds the old one. They are no-ops when `field` is empty or already `size`. `grid::centre_of(d: f64, dn, sn) = (d + ½)·sn/dn − ½` is the shared cell-centre-aligned axis map.
- **CORE-R69** `grid::lattice_for_aspect(aspect, max_nodes) -> Size` is the uncapped shape behind `lattice_for` (CORE-R48): the largest lattice of that aspect with `w·h ≤ max_nodes`, at least 1×1 and at most `u16::MAX` per axis. It never panics (a degenerate aspect gives 1 column; `max_nodes = 0` ⇒ 1×1). `lattice_for(display, max, bucket)` is `lattice_for_aspect(snapped aspect, max)` clamped to `display`.
- **CORE-R70** `SplitMix64::mix(z)` (a `const fn`) is the SplitMix64 finaliser, and `next_u64` is `mix` of the Weyl state. `rng::hash01(key) ∈ [0, 1)` is the top 53 bits of `mix(key)`, a stateless per-key uniform. `rng::cell_key(x, y)` packs `x` into the high and `y` into the low 32 bits, so distinct cells get distinct keys.

### Science titles and categories (M11)

Every scene shows a short science title at the bottom-left, drawn once, centrally, by `Stage` (ADR-0014). Scenes supply only data. Title content rules are GEN-R12; the scene-side layout rule is GEN-R13.

- **CORE-R71** `Meta.title: &'static str` is a `Phenomenon · mechanism` string (content rules: GEN-R12). `Meta.captions: &'static [&'static str]` lists every caption the scene's `caption()` can return (empty for a single-act scene). `Generator::caption(&self) -> Option<&'static str>` defaults to `None`; a scene with acts returns the live act's caption, a `&'static str` from `Meta.captions`, so it cannot allocate (GEN-R11). `title::Title::new(title, caption)` splits `title` at its first ` · ` into `phenomenon` and `mechanism` (the whole string and an empty mechanism when there is no separator), then replaces `mechanism` with the caption when it is `Some`. `Title::of(&generator)` is `Title::new(meta().title, caption())`, the one way scenes and `Stage` build a live title. `Title` is `Copy`, holds only `&'static str` and never allocates.
- **CORE-R72** `title::ascii_of(c: char) -> Option<char>` defines the title charset (ADR-0014): printable ASCII (`' '..='~'`) maps to itself, `·` and `–` map to `-`, and `á`, `é`, `ö` map to `a`, `e`, `o`; every other char gives `None`. Every allowed char is one cell wide, so a title's ASCII form is as wide as its Unicode form. `Title::width(form)` is the display width (`unicode-width`) of `Form::Phenomenon` (the phenomenon alone) or `Form::Full` (`phenomenon · mechanism`, or the phenomenon alone when the mechanism is empty).
- **CORE-R73** `Title::fit(&self, size) -> Option<Form>` is pure and allocation-free. With `limit = ⌊3·w/5⌋` it returns `Full` if `width(Full) + 2 ≤ limit`, else `Phenomenon` if `width(Phenomenon) + 2 ≤ limit`, else `None`, and always `None` when `h < 6`. The `+ 2` is the gutter and pad cells of CORE-R74. A form is shown whole or not at all, so a title is never clipped mid-word, and the chosen form never gets shorter as `w` grows. `Title::full_fits_from(&self) -> usize` is `⌈5(n + 2)/3⌉` for a full form of `n` cells: the narrowest width from which `fit` returns `Full` (at heights ≥ 6), derived from the 3/5 rule.
- **CORE-R74** `title::draw(canvas, title: &Title, age: f64)` draws the fitted form on row `h − 1` with the same cell layout as `draw::label(canvas, 0, h − 1, …)` (CORE-R67): an `Ink::BLANK` gutter cell at column 0, the text from column 1, and one `Ink::BLANK` pad cell after it. It touches no other cell, so half-block art keeps the rest of the row. Each char goes through `Canvas::put` as `Glyph::new(c, ascii_of(c).unwrap_or('?'))`, which also clears the cell background (CORE-R40), so ASCII mode output stays pure ASCII. Inks: the phenomenon is `Role::Text` level 170; the ` · ` separator and the mechanism are level 110. From `age = 8 s` (scene seconds the title has been on show, CORE-R75) both levels ease linearly to 90, reached at 10 s: `ink::level(lerp(base, 90, clamp((age − 8)/2, 0, 1)))`, with non-finite `age` treated as 0. This is deterministic, and frames at t ≤ 8 s are unchanged by it. `title::span(size, title) -> Option<(i32, Range<i32>)>` returns the row and the column range that `draw` writes (`0..width + 2`), or `None` when `fit` hides the title. `draw` never panics for any size ≥ 1×1 and never allocates.
- **CORE-R75** `Stage::render` draws the title (CORE-R74) after `generator.render` and before the swap, from `meta().title`, `generator.caption()` and its age: `ctx.time` minus the `ctx.time` at which `caption()` last changed (checked after every `step`; 0 at construction). A new act's caption therefore shows at full strength and fades like the first one. Every consumer of `Stage` (runtime, snapshots, contract, props, alloc and bench suites) sees the same frame. `Stage::set_title_visible(bool)` (default `true`) switches it; when hidden, the frame is exactly the generator's. The flag survives `resize`. A panic inside `generator.render` still leaves the previous complete frame (CORE-R21).
- **CORE-R76** `draw::label_right(canvas, y, s, ink) -> i32` is the right-aligned mirror of `draw::label` (CORE-R67): an `Ink::BLANK` cell in the last column `w − 1`, `s` ending in column `w − 2`, and an `Ink::BLANK` cell just before its first char. Chars are counted, one cell each (CORE-R4), and the text is clipped at column 0. It returns the column of the leading blank (negative when clipped), so a scene can shorten or drop a readout that would reach the title span (GEN-R13). `title::readout_room(size, &Title) -> usize` is `min(w − 4 −` the span's end`, ⌊w/2⌋)` (saturating; `min(w − 2, ⌊w/2⌋)` when the title is hidden): the longest `label_right` text on row `h − 1` that keeps at least 4 blank cells between the title's text and its own (the title's pad, the readout's leading blank and two more), so title and readout read as two units, not one sentence, and that takes at most half the row, so on narrow canvases the row stays art with a name and a number rather than one line of text. Title-row readouts are inked `Text` at `title::READOUT_LEVEL` (90, the level the whole title dims to, CORE-R74), so the numbers never outshine the scene's name, even once it has dimmed. Neither function allocates.
- **CORE-R77** (supersedes CORE-R47; ADR-0013) `Category` has exactly these eleven variants, listed in this order by `Category::ALL`. `label()` is the display name; `id()` is the label in kebab case, lower-cased with `&` dropped (printed by `sciart list`, CLI-R4), so the id a script sees names the same category a person does. Both are `const fn` returning `&'static str`, and ids and labels are each unique.

### Colour roles and tone mapping (M12, ADR-0015)

Three more semantic roles for fields (still never RGB, ADR-0004), and a tone-mapped path from a long-exposure `Density` to half-block `Pixels`. All are pure, allocation-free and never panic for any input. `Ink` stays two bytes.

- **CORE-R78** `Role::Phase` is a cyclic field: `level` is a phase angle, one full turn over 256 levels, so level 255 is next to 0. `ink::phase(radians: f64) -> Ink` gives `round(frac(radians / 2π) · 256) mod 256` for any finite angle, negative or beyond 2π (NaN or ±∞ ⇒ 0). `ink::phase_value(ink) -> f64` returns `level · 2π / 256 ∈ [0, 2π)`, which is the exact inverse on levels. In a `Dots` cell (CORE-R41), Phase dots all have intensity 0, so the last dot set wins: a phase is not an intensity.
- **CORE-R79** `Role::Blackbody` is temperature on a log scale: level 0 ⇔ `ink::BLACKBODY_MIN_K` = 1000 K, level 255 ⇔ `ink::BLACKBODY_MAX_K` = 30 000 K, and level `255 · ln(T / 1000) / ln 30` between them. `ink::blackbody(kelvin: f64) -> Ink` rounds and clamps (NaN ⇒ level 0). `ink::blackbody_kelvin(ink) -> f64` returns `1000 · 30^(level/255)`, so `blackbody(blackbody_kelvin(i)) == i` for every level.
- **CORE-R80** `Role::Ramp(Ramp)` is a sequential field in a named ramp (level 0 = low, 255 = high, like `Seq`). `Ramp` is a closed enum `Ember, Ice, Ferroin, HAlpha, Aurora, Plasma, Starlight, Sulfur, Cobalt, Eosin, Sienna, Infrared` (M12 added `Starlight`, the unresolved light of old stars, `Sulfur`, the chrome yellow of a *Physarum* plasmodium, `Cobalt`, deep ultramarine → cobalt blue → pale silver-blue, and `Eosin`, wine-rose → eosin rose-pink → pale pink-lilac; M13 added `Sienna`, dark sienna → rust → tan → cream for Jupiter-family planets, and `Infrared`, a meteorological IR enhancement curve grey → cyan → green → yellow → orange → pale rose-white). `Ramp::ALL` lists all 12 in that order, and `Ramp::name()` is a unique lower-case `&'static str` (`ember`, `ice`, `ferroin`, `halpha`, `aurora`, `plasma`, `starlight`, `sulfur`, `cobalt`, `eosin`, `sienna`, `infrared`). `ink::ramp(ramp, v)` maps `v ∈ [0, 1]` like `ink::seq` (clamped, NaN ⇒ 0), and `ink::seq_value` reads it back exactly. `size_of::<Ink>() == 2`.
- **CORE-R81** `raster::Tone::asinh(knee: f32, white: f32) -> Tone` is a tone curve for long exposures (Lupton-style asinh: linear for faint values, logarithmic for bright ones): `t(v) = asinh(v / knee) / asinh(white / knee)` on `[0, white]`, 1 above `white`, and 0 for `v ≤ 0` or NaN. A non-finite or non-positive `knee` or `white` is replaced by 1, and `knee` is raised to at least `white / 1000`: a stretch beyond 1000 : 1 is more than the table below resolves to 2 levels. The curve is stored as a `Tone::LUT` = 1024-entry table of levels `ink::level(255 · t)`, sampled at `v = white · (i / 1023)²`, so bins are finest near zero, where asinh is steepest. `Tone::level(v: f32) -> u8` looks up the nearest sample. It is non-decreasing in `v`, 0 at `v ≤ 0`, 255 at `v ≥ white`, and within 2 levels of `255 · t(v)` everywhere. Building a `Tone` does not allocate (the table is inline), so scenes rebuild it in `resize` when their exposure depends on the size. `Density::to_pixels(&self, pixels: &mut Pixels, tone: &Tone, ink: impl FnMut(u8) -> Ink)` sets every pixel `(x, y)` from the sum of its 2 × 2 dot block `(2x..2x + 1, 2y..2y + 1)`, so a `Density` and a `Pixels` over the same cells line up exactly. A block that sums to level 0 becomes `Ink::BLANK` (empty, so the background shows), any other block becomes `ink(level)`, and a pixel with no full block in the density becomes `Ink::BLANK`. It writes every pixel in one pass and never allocates.

### Raster helpers (M12)

- **CORE-R82** `Dots::disc(x, y, r, ink)` lights the filled disc of radius `r` (dot units, so round on screen) about `(x, y)`: every dot whose centre lies within `r`, plus the dot nearest the centre (so `r < ½` is one dot). It is clipped to the lattice, with cost bounded by the clipped box, so a huge `r` stays cheap. A non-finite centre or radius, or `r < 0`, lights nothing. Line-art scenes use it for bobs, heads, beads and the Brownian grain's collision beads.
- **CORE-R84** `Pixels::cell_bg(x, y)` is the one ink standing for cell (x, y)'s two pixels: the more intense non-empty one (the top on a tie; `stronger(top, bottom)`, CORE-R87), else `Ink::BLANK` (also off the buffer). `Dots::blit_over(&self, canvas, under: &Pixels)` writes the same cells, glyphs and inks as `blit`, with `under.cell_bg(x, y)` as each written cell's background, and leaves unlit cells untouched; in ASCII mode (no half blocks) it is plain `blit`. It lets a `Pixels` layer (a glow, a lattice) carry on under braille dots instead of stopping at the first dotted cell (M12: electron_orbitals, particle_accelerator, radioactive_decay).
- **CORE-R85** `raster::Glow` is a long-exposure `f32` buffer at `Pixels` resolution (`w × 2·h`, one value per pixel: an eighth of a `Density`'s memory): `new`/`resize(cells)` zero it (reusing the buffer), `clear`, `decay(k)` multiplies by k clamped to [0, 1] (NaN and k ≥ 1 leave it; shared with `Density::decay`), `splat(x, y, kernel, scale)` adds `scale·w` at pixel `(px + dx, py + dy)` for each `(dx, dy, w)` of the kernel, where `(px, py)` holds dot `(x, y)` (rounded to the nearest dot, 2 × 2 dots a pixel), ignoring non-finite input and off-buffer pixels; `get(x, y)`; `to_pixels(&mut Pixels, &Tone, ink)` sets each pixel 1:1 from its value through the tone (level 0 ⇒ blank, else `ink(level)`) and empties pixels outside the glow. Allocation-free after resize (M12: electron_orbitals' cloud glow and particle_accelerator's collider glow, which each had their own copy).
- **CORE-R86** `Pixels::backdrop(&self, canvas: &mut Canvas)`, called after `blit` and after a scene has drawn glyphs over the picture (sprites, line art, labels), gives each such cell its `cell_bg` (CORE-R84) as its background. The cell's char and foreground ink are kept. Cells that already have a background, half and full blocks (`▀ ▄ █`), and cells over two empty pixels are left alone; a space over pixels counts, since over a picture only a label writes one. It does nothing on an ASCII canvas, which has no half blocks to match, and never allocates. So a strut or a caption over a half-block sky reads as drawn on the sky, not as a black box.
- **CORE-R87** `raster::stronger(a, b) -> Ink` is the more intense of two inks, by the measure a `Dots` cell uses to pick its ink (CORE-R41: `level`, `|level − 128|` for `Div`, 0 for `Phase`), `a` on a tie; an empty ink loses to any drawn one. It is the one rule for keeping a single colour when a cell's two pixels must become one glyph (a `Pixels::blit` ASCII fallback) or one background (`cell_bg`, CORE-R84) (M12: cosmic_microwave_background, globular_cluster, stellar_nursery, galaxy_collision and pulsar each had their own comparison).
- **CORE-R88** `ink::class_kelvin(classes, u, v) -> f64` draws a temperature from a spectral-class mix: `classes` holds `(cumulative fraction, lowest K, highest K)` rows in increasing fraction; the first row with `u < fraction` is picked (the last row past the end), and the temperature is `lo + (hi − lo)·v`. An empty table gives NaN (M12: starfield's naked-eye mix and globular_cluster's old population).
- **CORE-R89** `Pixels::dissolve(floor)` fades a glow's faint fringe smoothly into the empty sky, so it ends in the terminal's black rather than on a ramp's tinted floor. A non-empty, non-`Phase` pixel of intensity `i < floor` (as for `stronger`) is emptied when `i < floor/2`, and for `i ∈ [floor/2, floor)` its intensity becomes `i·smoothstep((i − floor/2)/(floor/2))` (a `Div` pixel keeps its side of 128), emptied if that rounds to 0. *(M14, ADR-0017: no dither)* The fade is a pure function of the pixel's own intensity, continuous and non-decreasing in it, so a uniform field stays uniform: there is no ordered or noise pattern (the M12 white-noise threshold is retired). Pixels at or above `floor`, `Phase` pixels and `floor = 0` are untouched; allocation-free (M12: pulsar's beams, globular_cluster's glow, starfield's Milky Way).
- **CORE-R91** `raster::ascii_ramp_cell(top, bottom) -> Option<(char, Ink)>` is the `Pixels::blit` ASCII fallback for half-block pictures of light: the `stronger` (CORE-R87) of the cell's two pixels, drawn as its level on `raster::ASCII_RAMP` = `.:-=+*#%@` (entry `level · 9 / 256`, so level 0 is `.` and 255 is `@`) in that pixel's ink; `None` (the cell is left untouched) when both pixels are empty (M12: black_hole defined it and gravitational_lensing imported it from that scene).

### Deterministic trigonometry (M12)

- **CORE-R90** `sciart_core::trig::{sin, cos, sin_cos}` (f64), `{sinf, cosf, sin_cosf}` (f32), and the prelude trait `Trig` with methods `sin_det`, `cos_det`, `sin_cos_det` on `f64` and `f32` give the platform libm's single-function results, bit for bit, whatever the build profile, inlining, LTO or codegen-unit split: `x.sin_cos_det() == (x.sin_det(), x.cos_det())` and each equals `sin`/`cos` evaluated on its own. Why: LLVM fuses a `sin` and a `cos` of the same argument in one function into one `sincos` call (`__sincos_stret` on Apple platforms), whose sine differs from libm's `sin` in the last bit for about 0.2 % of arguments; whether a pair lands in one function depends on inlining, which differs between dev and release builds, so the same seed gave different frames (M12: molecular_dynamics' Box–Muller start velocities, amplified by the chaotic gas). Each is a non-inlined wrapper around one libm call, so no function ever holds both halves of a pair (ADR-0016). Every trig call in the workspace goes through them: `clippy.toml` bans `f64::{sin, cos, sin_cos}` and `f32::{sin, cos, sin_cos}`, and only `trig.rs` may call them (GEN-R6).

### Shared helpers lifted in the M12 closing review

- **CORE-R92** `Glow::splat_bilinear(x, y, w)` adds `w` at a continuous *pixel* position (integers are pixel centres) split bilinearly over the four nearest pixels, weights `(1−fx)(1−fy), fx(1−fy), (1−fx)fy, fx·fy`. Off-buffer pixels are skipped, so the in-bounds share of `w` is conserved exactly when all four are on the buffer, and no pixel beyond distance 1 on either axis is touched; non-finite `x`, `y` or `w` deposit nothing. `Glow::values()` / `values_mut()` expose the row-major buffer for scene-side filters (a blur) between splatting and toning. Allocation-free (M12: galaxy_collision had a private copy; pulsar's beam rays and globular_cluster's glow used nearest-pixel `splat`, which quantised a moving source into spokes and stair steps).
- **CORE-R96** `Glow::stroke(a, b, kernel, scale)` exposes the dot-space segment `a → b` by `splat`ting `kernel` at `scale` at the midpoints of `n = clamp(⌈len/2⌉, 1, 2048)` equal parts (one splat per pixel of length, a pixel being 2 dots), so the exposure per pixel of length does not depend on the length; a non-finite length draws nothing. `raster::STROKE_KERNEL` is the 3 × 3 stroke splat (centre 0.36, edges 0.12, corners 0.04; sum 1), and the `const fn raster::halo_kernel::<N>(r)` builds a round halo over the `(2r + 1)² = N` square, weights `(1 − d²/(r + ½)²)²` (1 at the centre, 0 outside radius `r + ½`; a wrong `N` fails the build). Allocation-free (M12: double_pendulum and three_body each had a private copy).

### Stellar discs (M12)

- **CORE-R93** `stellar::limb_darkening(mu, (u1, u2)) -> f64` is the quadratic limb-darkening law `1 − u1(1 − μ) − u2(1 − μ)²` (the linear law is `u2 = 0`), with `μ` clamped onto `[0, 1]` and NaN read as the limb (`μ = 0`).
- **CORE-R94** `stellar::brightness_temperature(t_centre, i) -> f64` is the 550 nm brightness temperature of a surface element at intensity `i` of the centre's, by Wien's law `1/T = 1/t_centre − (λ/c₂)·ln i` with `λ/c₂ = stellar::WIEN_550`; `i` is clamped onto `[10⁻⁶, 1]` (NaN ⇒ 10⁻⁶), so `T` is finite, positive, non-decreasing in `i` and never above `t_centre`. With `Role::Blackbody` (CORE-R79) it colours a limb-darkened disc in true colour, reddening and dimming toward the limb.
- **CORE-R95** `raster::disc_cover(x, y, c, r) -> f64` is the share of pixel `[x, x + 1) × [y, y + 1)` inside the circle of radius `r` about `c`, estimated from the pixel centre's distance `d` as `clamp(r + ½ − d, 0, 1)` (NaN ⇒ 0). `raster::disc_pixels(c, r, f)` calls `f(x, y, cover)` for exactly the pixels with `cover > 0`, each once, row by row and left to right, unclipped, and visits nothing for non-finite input or `r < 0`.

### Title helpers (M12)

- **CORE-R83** `title::stable_readout_room(size, &Meta) -> usize` is the least `readout_room` (CORE-R76) over the scene's title with no caption and with each of `meta.captions`, taken at width `w` and at every wider width up to the largest `Title::full_fits_from()` of those titles (CORE-R73). So it never exceeds the room of any caption at `w`, and it is non-decreasing in `w`: a narrower terminal can fall back to the shorter phenomenon-only title and free room, and this helper does not pass that room on. From that upper width each title's span is fixed and its room only grows, so the minimum is reached. Captioned scenes size title-row readouts by it in `resize`, so a readout never comes and goes with the beat. It does not allocate.

### Value noise (M13)

- **CORE-R97** `rng::value_noise(salt, x, y, cell) -> f64` is smooth 2-D value noise in `[0, 1]`: lattice corners at multiples of `cell` carry `hash01(salt ^ cell_key(i, j))` (CORE-R70), blended bilinearly with `ease::smoothstep` weights, so at a lattice corner it equals that corner's hash exactly and it is continuous everywhere. It is stateless and deterministic (same arguments ⇒ same bits), never panics or allocates. Lifted from `stellar_nursery` for the M13 cosmos scenes, which previously would each have carried a copy.

### Lattice Boltzmann and complex tridiagonal solves (M13)

- **CORE-R98** `lbm` holds the D2Q9 velocity set (`CX`, `CY`, `OPP`, weights `W`; rows grow downward like the screen) and the two-relaxation-time (TRT) collision on *shifted* populations `h_i = f_i − w_i` in `f32` (Lehmann et al. 2022): `heq(δρ, uₓ, u_y)` is the shifted second-order equilibrium `w_i (δρ + ρ(3 c·u + 4.5 (c·u)² − 1.5 u²))`, `ρ = 1 + δρ`, whose zeroth and first moments are exactly `δρ` and `ρu` in exact arithmetic; `collide(h, ω⁺, ω⁻) -> (ρ, uₓ, u_y)` relaxes the even and odd parts of each opposite pair at `ω⁺` and `ω⁻`, conserving the node's mass and momentum (to `f32` rounding), and returns its pre-collision moments; `tau_minus(τ, Λ) = ½ + Λ/(τ − ½)` gives `τ⁻` from the magic parameter (`Λ = ¼` is the most stable). A node at equilibrium is a fixed point of `collide`.
- **CORE-R99** `lbm::Lattice` is a `w × h` D2Q9 lattice with nine SoA `f32` planes of shifted populations, a spare buffer, moment grids `ρ`, `uₓ`, `u_y` and a solid mask (`Lattice::new(size, solid)` starts at rest, `f = w`). `stream_collide(ω⁺, ω⁻, wrap_x)` is one fused pull stream + TRT collide into the spare buffer, periodic in y and, with `wrap_x`, in x; a pull from a solid node takes the node's own opposite population (halfway bounce-back), solid nodes are written at rest; without `wrap_x` columns 0 and `w − 1` of the spare buffer are left to the caller's boundary conditions (`next_and_moments()` hands them over). It writes each fluid node's pre-collision moments. `swap()` makes the spare buffer current; `step_periodic` is both. A fully periodic step conserves total mass (`Σρ` in `f64`) to `f32` rounding (relative 1e-8 per step and 1e-6 over 200 steps on a 64 × 64 lattice) and momentum on a lattice without solids, keeps a uniform flow uniform, and damps a shear wave at the TRT viscosity `ν = (1/ω⁺ − ½)/3` within 2 %. `equilibrate()` rebuilds every population from the stored moments (solid nodes at rest), `mass()` is `Σρ` in `f64`, `healthy(band)` checks that every moment is finite and every `ρ` is in `band`. After construction nothing allocates. Why: vortex_street's kernel (≈ 7 ns a node) lifted unchanged for kelvin_helmholtz, so both run the same, tested physics; the street's frames stay bit-identical (KH-A1).
- **CORE-R100** `ode::C64` is a plain `Copy` complex number (`re`, `im`; `+ − ×` and `/`, `conj`, `norm_sqr`, `scale`; no dependency). `ode::tridiag_solve_c(sub, diag, sup, rhs, scratch) -> bool` is `tridiag_solve` (CORE-R59) over `C64`: the Thomas algorithm in place into `rhs` with caller-owned `scratch`; mismatched lengths or a zero or non-finite pivot return `false` with `rhs` untouched, and it never allocates. For a matrix solved many times (a Crank–Nicolson step with fixed coefficients) `tridiag_factor_c(sub, diag, sup, inv_pivot, c_prime) -> bool` stores the elimination once (same failure rules, outputs untouched on failure) and `tridiag_apply_c(sub, inv_pivot, c_prime, rhs)` solves with it; the pair gives the same `x` as the one-shot solve to rounding (relative 1e-12 on diagonally dominant systems) and does nothing on mismatched lengths. Why: quantum_double_slit's unitary ADI Crank–Nicolson step needs complex tridiagonal solves on every grid line, twice per step.
- **CORE-R101** (M14) `Generator` has `fn prepare(&mut self) {}` (default no-op). `Stage::render` calls `prepare` exactly once and then `render`, on every call, after any `step`s and `resize`. A generator that never overrides it behaves exactly as before (GEN-R20).
- **CORE-R102** (M14) `grid::SampleMap` has a cubic mode: separable Catmull-Rom with the four taps and weights per axis precomputed when the map is rebuilt (edge-clamped, cell-centre convention of CORE-R52), so sampling a field costs 16 multiply-adds per pixel and no transcendental maths. It is exact at the source centres for equal sizes, reproduces linear ramps exactly, and its result is clamped to the four central source values' range so it never overshoots into new colours.
- **CORE-R103** (M14) `Glow::blur121()` blurs in place with the separable binomial kernel `[1 2 1]/4 ⊗ [1 2 1]/4`, edges clamped, as `0.25·(prev + 2·cur + next)` per pass. It walks rows only with one scratch row sized in `resize`, so it never allocates. A constant field is a fixed point, and interior mass is conserved. Lifted from motility_clustering and dicty_aggregation (M13 follow-up).
- **CORE-R104** (M14) `SampleMap::row(src, y) -> MapRow` resolves a destination row's two source rows and weight once; `MapRow::at(x)` is bit-identical to `sample(src, x, y)`, including 0 for the empty map or a wrong-size source, and `sample`/`bilerp` are force-inlined. Why: a per-pixel `sample` was an out-of-line call and the top profile entry in radical_chain.
- **CORE-R105** (M16, ADR-0019) Iso-contours into braille: `Dots::contour(values, w, h, level, to_dot, ink)` draws the level set `v = level` of a row-major `w × h` node field by marching squares, one dot thick: in every cell of four nodes `(i, j), (i+1, j), (i+1, j+1), (i, j+1)` whose values straddle `level` (a node is *below* when `v < level`), the crossing on each straddling edge is placed by linear interpolation and the crossings are joined by `Dots::line` (two crossings: one piece; four, a saddle: the pairs in edge order). `to_dot(x, y)` maps continuous node coordinates (node `(i, j)` at `(i, j)`) to dot coordinates. `Dots::contour_by(…, ink: FnMut(i, j) -> Option<Ink>)` picks the ink per cell (or skips it with `None`), so scenes colour a contour by sign, age or a sampled variable; `Dots::contour_cell(corners, level, (i, j), to_dot, ink)` draws one cell, for scenes that cull cells themselves. A closed level set (a circle's) is drawn as a closed curve on its radius (within one dot). Fields shorter than `w·h`, `w < 2` or `h < 2` draw nothing; non-finite values or crossings draw nothing in their cell; nothing allocates (CORE-R41).
- **CORE-R106** (M16, ADR-0019) Refined contour cells: `Dots::contour_cell_refined(corners, level, (i, j), k, to_dot, ink)` splits the cell into `k × k` sub-cells whose corner values are bilinear in the four node values and draws each sub-cell the level crosses with `contour_cell`, mapping sub-cell coordinates through `to_dot` at node coordinates `(i + u/k, j + v/k)`. So where a node spans many dots the level set is the bilinear surface's (a hyperbola within the cell, to within `1/k` of a cell) rather than one chord per cell, and curves stay smooth. `k ≤ 1` is exactly `contour_cell`; `k` is capped at 16; nothing allocates. Lifted from vortex_street and hurricane (M16).
- **CORE-R107** (M17, ADR-0020) Fixed-threshold stipple: `raster::stipple_keep(salt, x, y, p) -> bool` is `hash01(salt ^ cell_key(x, y)) < p` (CORE-R70), false for `p ≤ 0` or NaN and true for `p ≥ 1`; `Dots::stipple(x, y, p, salt, ink)` lights dot `(x, y)` when it is kept (off-lattice dots ignored). Over many dots the kept share is `p`; layers with different salts are independent; and keeping is monotone in `p`, so a cloud whose density changes smoothly gains or loses dots only where it crosses their fixed thresholds: no shimmer and few changed cells per frame. The probability clouds of `electron_orbitals`, generalised for GEN-R26.
- **CORE-R108** (M18, ADR-0021) Stipple atoms: `Dots::stipple_puff(cx, cy, sigma, peak, salt, ink)` draws a small Gaussian probability cloud about `(cx, cy)` (dot units): every dot within `3σ` of the centre is lit when `stipple_keep(salt, x, y, peak·e^(−r²/2σ²))` (CORE-R107), and the dot nearest the centre is always lit when `peak > 0`, so an atom never vanishes. Clipped to the lattice; a non-finite centre or σ, `σ ≤ 0`, or `peak ≤ 0` lights only the centre dot (or nothing for `peak ≤ 0` or a non-finite centre). Monotone in `σ` and `peak` (a swelling atom only gains dots) and allocation-free. The atoms of GEN-R26's molecules rule: wave sources, beads, food flakes, firefly flashes.
