# SPEC-003: Runtime & rendering

**Crates**: `crates/sciart` (runtime), `crates/sciart-render` · **Milestones**: M1 (minimal), M2 (full) · **Status**: Implemented through M3; RND-R6/R7 in M10; RT-R12/R13 and RND-R8/R9 in M11; RND-R10..R12 in M12

## Runtime (pure state machine, no terminal access)
- **RT-R1** `Runtime` owns the active generator list, the current index, a `Canvas`, a `Ctx`, and a `FixedStep`. It is driven only by `tick(elapsed)`, `handle(Action)` and `resize(Size)` — fully unit-testable.
- **RT-R2** `tick` runs the generator's `update` for the steps returned by `FixedStep`, then `render`s into the canvas. Both calls are wrapped in `std::panic::catch_unwind`.
- **RT-R3** On panic: the generator is added to the quarantine set, the canvas keeps the last good frame, and a `Notice` is recorded. In `sim` mode the runtime switches to the next healthy generator.
- **RT-R4** If every generator is quarantined, `Runtime::status()` is `AllFailed`; `tick` becomes a no-op; the app keeps running until quit.
- **RT-R5** (M2) With `with_interval(secs)`, auto-cycle once `secs` of unpaused *wall* time have elapsed since the last switch, to the next healthy generator ≠ current in the cycle order (RT-R13; before M11: a random one). With fewer than two healthy generators there is no auto-cycle. Every switch (auto, `Next`, `Prev`, after a panic) restarts the timer; `Reset` does too.
- **RT-R5a** (M2) History: each newly shown generator is pushed (bounded to 64). `Prev` returns to the most recent earlier, non-quarantined entry in history; with none it is a no-op.
- **RT-R6** (M2) `handle(Action) -> Flow`. Actions: `Next`, `Prev`, `TogglePause`, `Reset`, `ToggleHud`, `CycleTheme`, `Quit` (⇒ `Flow::Quit`, all others `Flow::Continue`). Pause freezes simulation and the auto-cycle timer; `Next`/`Prev`/`Reset` work while paused. The runtime owns view state (`hud()`, `theme()`, `paused()`). With `AllFailed`, generator actions are no-ops.
- **RT-R7** Switching generator (or `Reset`) builds a fresh instance, calls `resize` before its first `update`, and renders one frame immediately so the screen never goes blank (also while paused).
- **RT-R9** (M2) `keys::action_for(KeyEvent) -> Option<Action>` maps only key *presses*: `n`/`→` Next, `p`/`←` Prev, `space` TogglePause, `r` Reset, `h` ToggleHud, `t` CycleTheme, `q`/`Esc`/`Ctrl-C` Quit; letters are case-insensitive; everything else is ignored.
- **RT-R10** (M2) `FpsMeter::record(frame_secs)` keeps an exponential moving average (α = 0.1) of `1/frame_secs`; the first sample seeds it; non-positive or non-finite samples are ignored; `fps()` is 0 before any sample.
- **RT-R8** (M3) `Pacer::new(fps, low_fps, idle_after)`: `record(elapsed)` accumulates idle time; `input()` (any key event, bound or not) resets it; `focus(false)` / `focus(true)` track terminal focus (`focus(true)` also resets idle). `low_power()` ⇔ unfocused or idle ≥ `idle_after`; `fps()` is `min(low_fps, fps)` in low power, else `fps`.
- **RT-R11** (M3) Simulation speed is independent of FPS down to 4 FPS: the runtime's `FixedStep` allows up to `MAX_STEPS = 15` steps per frame (ADR-0003 amended), so one `tick(0.2)` runs 12 steps.
- **RT-R12** (M11, ADR-0014) The canvas title (CORE-R75) is visible iff the `title` setting is on (CFG-R6, CLI-R7) and the HUD is off: the runtime applies `Stage::set_title_visible(title && !hud)` to every stage it builds and on `ToggleHud`. With the HUD on, the HUD shows the title instead (RND-R9). While the RT-R4 error line is shown there is no stage, so there is no canvas title either. Toggling the HUD while paused re-renders the current frame once without stepping (simulation state and `ctx.time` unchanged), so neither the title nor its absence goes stale under a frozen frame. `Runtime::title()` returns the live `Title` (`meta.title` with the current `caption()`, CORE-R71), or `None` with no stage or with the `title` setting off.
- **RT-R13** (M11, ADR-0013) `sim` walks a cycle order built once in `Runtime::new` from the runtime's seeded RNG (ADR-0008). Entries are grouped by `meta.category`; the order of the non-empty categories is shuffled, then each group is shuffled; the cycle order is the round-robin interleave that takes the next entry of each category in turn, skipping exhausted categories. It is a permutation of the entries, identical for a given seed, and `order[i]` and `order[i + 1]` share a category only if every entry of `order[i + 1..]` is in that category. `sim` starts at `order[0]` (unless `start` is given). Auto-cycle, `Next` and the switch after a panic go to the next healthy entry after the current one in the order, wrapping and skipping quarantined entries and the current one; the walk resumes after the entry activated last, including one just quarantined; `Prev` still walks history (RT-R5a).
- **RT-R14** (M14) The steady-state frame loop allocates nothing: after warm-up, `Runtime::tick`, `paint`, the HUD draw and the keep-awake status line perform no heap allocation per frame (status text is formatted into reused buffers). Checked with the counting allocator (ADR-0009).
- **RT-R15** (M14) Each drawn frame reaches the terminal as one buffered write: output is encoded into a buffer sized for a full frame and reaches the terminal as a single write and flush per `draw`; a non-empty frame is wrapped in a synchronized update (DEC private mode 2026; terminals without it ignore the mode) so it never tears, only SGR parameters that changed are sent, and an unchanged frame writes nothing.
- **RT-R16** (M15, ADR-0018) Resource budget: restoring the M11 look keeps M14's gains. Over every registered scene at 200×50 (seed 42, 10 s each, stepped and drawn at 30 FPS through the real frame pipeline: paint, diff, encode), the mean terminal output is at most 20 480 bytes per frame and the mean number of changed cells at most 880 per frame (M14: 18 812 B and 806; before M14: 58.6 KB). Output is deterministic, so this is a test; CPU time stays a release-mode check under GEN-R8 (`rs-cost`: pipeline mean at most M14's 0.63 ms; `rs-worst`: every scene's worst frame under 2 ms at 200×50).

## Rendering (`sciart-render`)
- **RND-R1** `Theme::color(ink, x, y) -> Rgb` is a pure function (no RNG, no time): same inputs ⇒ same color, so frames never strobe.
- **RND-R2** Built-in themes: `astro` (default, role-based palette), `rainbow` (hue hashed from `(x, y)` + level as value), `mono` (grey ramp by level). `Theme::from_name` parses case-insensitively.
- **RND-R3** `paint(canvas, theme, buf: &mut ratatui::buffer::Buffer)` writes every canvas cell into the buffer area; `Role::Background` cells are written as a space with default colors.
- **RND-R4** (M2, extended M3, fitting post-M8) `Hud { generator, fps, theme, seed, keep_awake, low_power, paused, quarantined }` renders as a ratatui widget on the **last row** of the area (reversed style), touching no other row; the canvas size is unchanged. Full text: `<name> | <fps> fps | <theme> | seed <n> | <keep_awake status>` then ` | LOW-POWER`, ` | PAUSED` and ` | <k> quarantined` when applicable, then ` | n p space r h t q`. ASCII only. When the full text is wider than the area it is **fitted, not clipped** (`Hud::fit(width)`): drop key hints, then seed, then theme; shorten keep-awake to `ka:<state>`; drop fps; drop keep-awake; then elide the scene name at its end with `~` (minimum 2 columns) and finally drop it. State flags are never dropped or shortened while `width` ≥ the width of the flags alone; only below that is the flags text cut with a trailing `~`. The fitted text is never wider than the area, is a pure function of the fields and the width, and costs at most one `String` allocation per frame.
- **RND-R5** `TerminalGuard` enters raw mode + alt screen + hidden cursor and enables focus-change reporting (M3); it restores all of it on `Drop`, and on panic through a hook that runs before the default hook prints.
- **RND-R6** (M10) Colormap roles (ADR-0011): `Role::Seq` and `Role::Div` map `level` through a multi-stop gradient per theme. `astro`: `Seq` is inferno-like (deep violet → red → orange → pale yellow) and `Div` is cyan-blue ← near-background dark → orange. `rainbow`: `Seq` is turbo-like and `Div` is blue ← dark → red, both ignoring the per-cell hash. `mono` (grey ramps linear in CIE L*, unlike its object-role ramp whose floor is grey 40): `Seq` runs from near-black (L* 3.5) at level 0 to white at 255, so zero fields read as background, not a grey wash; `Div` keeps zero at the same near-black and shows the sign by brightness: positive climbs to white (L* 100), negative only to a dim grey (L* 45), so at equal `|v|` the positive side is always brighter (ΔL* = 55·|v|). Luminance is non-decreasing in `level` for every role except `Div`, whose luminance is non-decreasing in `|level − 128|` (RND-R1's property, amended).
- **RND-R7** (M10) `paint` sets the terminal background colour from `cell.bg` when `cell.bg.role != Role::Background` (theme-mapped like fg) and leaves it at the default otherwise (CORE-R40).
- **RND-R8** (M11) In `rainbow`, `Role::Text` ignores the per-cell hue hash and maps to a fixed neutral grey whose brightness is non-decreasing in `level` (RND-R1), so titles and labels read as text instead of confetti. `astro` and `mono` are unchanged.
- **RND-R9** (M11, amends RND-R4; ADR-0014) The HUD's name slot shows the scene's science title instead of its snake_case id: `Hud` carries the id and `Option<Title>` from `Runtime::title()` (RT-R12); with `None` the slot shows the id exactly as RND-R4 describes. The RND-R4 ladder is unchanged up to dropping keep-awake. After that, the slot steps from the full title to the phenomenon to the id, then elides the id with `~` and finally drops it. Each shorter name is used only when it fits whole, so an id wider than the phenomenon is never shown whole, only elided. The title is written in its ASCII form (`title::ascii_of`, CORE-R72), so the HUD stays ASCII-only, and fitting stays a pure function of the fields and the width with at most one `String` allocation per frame. The widget draws one reversed blank lead cell in column 0 and the text fitted to `width − 1` from column 1, so the name starts in the same column as the canvas title's text (CORE-R74) and does not shift when the HUD is toggled.
- **RND-R10** (M12, ADR-0015) `Role::Phase` (CORE-R78) maps to a closed loop with no seam: the colours of levels 255 and 0 are as close as any two neighbouring levels. `astro` is a soft isoluminant hue loop (every level's CIE L* within 5 of the others, and six phases a sixth of a turn apart are hues at least 30° apart). `rainbow` is a full-saturation HSV hue wheel (`h = level/256`). `mono` is a grey triangle in L*, from the RND-R6 floor at level 0 to L* 85 at level 128 and back. All three ignore the per-cell hash. A phase level is an angle, not an intensity, so RND-R1's brighter-level property does not apply to this role.
- **RND-R11** (M12, ADR-0015) `Role::Blackbody` (CORE-R79) maps to the Planck locus in sRGB: the colour of a blackbody at `ink::blackbody_kelvin(ink)` under the CIE 1931 2° observer, normalised to its brightest channel and, below 6500 K, dimmed so that its lightness climbs linearly in log T from L* ≈ 12 at 1000 K to the full colour, which is near white (every channel ≥ 235) at 6500 K. The table is built once from Planck's law and the Wyman–Sloan–Shirley fit of the colour-matching functions. `astro` and `rainbow` share it. Red dominates below 3000 K, blue is the largest channel at 10 000 K and above, and there the lightness stays at least L* 75. Luminance is non-decreasing in `level` up to the white point (6500 K, level 140) and falls gently above it, which amends RND-R1's property for this role. `mono` maps Blackbody to the grey of the same CIE L* as its `astro` colour (within 1.5), so a star is as bright in grey as in colour: a 5–6 kK star is near white, not the mid-grey its level would give as `Seq`.
- **RND-R12** (M12, ADR-0015) `Role::Ramp(r)` (CORE-R80) maps each named ramp through its own 256-level table, shared by `astro` and `rainbow` and built once from OKLCh (lightness linear in `level`, hue linear between the ramp's two ends, chroma lowered only where sRGB cannot hold it). Level 0 is near-black (L* ≤ 6), CIE L* is non-decreasing in `level` (to within 0.25 per level, the 8-bit rounding) up to L* ≥ 90 at 255, and the ramps' top-level colours are hues at least 15° apart (all but `Sienna`, which is told apart by chroma). `Starlight` (OKLCh hue 75° → 70°, chroma 0.035) alone has its chroma scaled by `min(1, 2t)` (`t = level/255`), so it runs near-black → neutral grey (levels ≤ 24 within 3 of grey in every channel) → pale warm white: the faint levels a halo or the Milky Way uses read as grey starlight, not sepia (an old population's integrated B − V ≈ 0.7 is pale yellow-white). `Sulfur` (OKLCh hue 80° → 110°, chroma 0.21) is yellow, not orange: at levels 128, 170 and 210 its HSV hue is in [48°, 66°] with red and green both more than 60 above blue, and at least 12° yellower than `Ember` at the same level. `Cobalt` (OKLCh hue 258° → 278°, chroma 0.17) is blue, not Ice's cyan: at levels 96, 128 and 170 blue exceeds green by more than 60 and green ≥ red. `Eosin` (OKLCh hue 358° → 325°, chroma 0.20) is rose. At levels 96, 128 and 170, red exceeds green by more than 50 and blue exceeds green by more than 25. Red leads blue by 15–80, unlike Ferroin's plum or Plasma's violet, where blue leads or ties, and unlike HAlpha's crimson, where red leads by about 100. `Sienna` (M13, OKLCh hue 38° → 75°, chroma 0.11) is a muted earth tone: at levels 96, 128, 170 and 210 red > green > blue and its HSV saturation is at least 0.2 below `Ember`'s at the same level. `Infrared` (M13, chroma 0.17) is an IR enhancement curve: its chroma is scaled by `clamp((t − 0.3)/0.12, 0, 1)` and its hue runs 215° → −25° over `t ∈ [0.3, 1]` only, so levels ≤ 76 are grey (within 3 in every channel), level 112 is cyan-teal (HSV hue 150°–185°), 140 green-yellow (80°–130°) and 200 orange (10°–40°). `mono` maps every ramp like `Seq` (RND-R6 floor), and all of them ignore the per-cell hash.
- **RND-R13** (M14) A cost probe (`pixi run rs-cost [scene ...] [--size WxH] [--secs N]`) drives scenes through the real `paint` and ratatui diff into a byte-counting crossterm backend and reports, per scene: update + render µs, paint µs, diff + encode µs, bytes per frame (mean, p95), changed cells per frame, and the art metrics of GEN-R17 (blockiness) and GEN-R18 (darkness) from the painted `astro` RGB.
- **RND-R14** (M14) Colour hysteresis: `paint` remembers the RGB last emitted for each cell's foreground and background. When a cell keeps its glyph and a colour moves by at most `HYSTERESIS` (2) in every channel from the emitted one, the emitted colour is kept, so the diff sends nothing for that cell. The error against the true colour never exceeds `HYSTERESIS` per channel (it is measured against the emitted colour, so it cannot drift), a change larger than the threshold is emitted exactly, and the memory resets on resize, theme change and every `Runtime::epoch` change (scene switch, reset, quarantine).
- **RND-R15** (M14) `paint` does no per-cell floating-point colour maths: every (theme, role) colour comes from a 256-entry table built once (`rainbow`'s per-cell hue from per-position hue factors rebuilt on resize: two multiplies per cell, since a full per-cell table would be about 57 MB at 500×150), and the colours are byte-identical to the RND-R1..R12 definitions. A blank cell with no background ink needs no foreground, and a cell's style carries only what changes its look, so no escape is sent for invisible attributes.
