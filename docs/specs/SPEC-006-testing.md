# SPEC-006: Testing & quality gates

**Status**: Implemented (all layers, including `alloc_free` and `spec_traceability`, cover all 41 scenes); TEST-R6..R8 (leak guards) specified for M11

## TDD workflow
1. Pick the next unchecked item in `docs/ROADMAP.md`.
2. Add/extend requirement IDs in the relevant SPEC if behavior is new.
3. Write a failing test whose name or doc comment cites the ID (e.g. `core_r10_advance_clamps_to_max_steps`).
4. Implement the minimum to pass; refactor; `pixi run rs-ci`.
5. Tick the roadmap item; commit (`feat(core): … [CORE-R10]`).

- **TEST-R2** Snapshot changes are reviewed with `cargo insta review`; never blindly accepted.
- **TEST-R9** (M12, amended M22, ADR-0023) `pixi run rs-ci` also runs the snapshot suite in an optimised build (task `rs-snap-release`), so a frame that changes with the optimiser (GEN-R6) fails the gate, not a user's `sciart` binary. Since M22 that build uses the `ci` profile (opt-level 3, many codegen units, no LTO, `panic = "unwind"`), which `rs-cost` and `rs-worst` use too; `sciart` installs keep the `release` profile. A source-rules test asserts `rs-ci` depends on that task and that the task builds with optimisation (opt-level 3).
- **TEST-R10** (M22, ADR-0023) Fast tests: `pixi run rs-test` runs every test of the workspace under `cargo nextest` (test binaries in parallel; doctests, if any, still run through `cargo test --doc`) on an optimised test build (opt-level ≥ 2) that keeps debug assertions and overflow checks. No test is dropped, skipped or weakened: the set of test names run by `rs-test` equals the set `cargo test --workspace` lists. A source-rules test asserts the task uses nextest and that the test profile keeps `debug-assertions` and `overflow-checks`. Target (reference machine, 14 cores): `rs-test` after editing one scene ≤ 60 s (M21: 173 s); measured before and after in docs/design/M22-lean-build-runtime.md.
- **TEST-R11** (M22, ADR-0023) Shared compiler cache: the pixi environment provides `sccache` and every cargo task runs with it as the rustc wrapper (`RUSTC_WRAPPER`), so a new checkout or workspace (which starts with an empty `target/`) reuses compiled crates. Builds stay correct without the cache (the wrapper is skipped when `sccache` is missing). Measured: a cold `rs-build` in a fresh checkout before and after.
- **TEST-R12** (M23) Terminal-environment hermeticity: the suite passes with `NO_COLOR` set to a non-empty value, `TERM=dumb`, and no `HOME`/`XDG_CONFIG_HOME`. A test that builds a crossterm reference calls `crossterm::style::force_color_output(true)` before it, so the reference never depends on ambient colour configuration; the application's own encoder is unaffected. Hosted CI runs the suite once with `NO_COLOR=1` (ADR-0024), and a test citing this ID asserts that the forced reference emits truecolour SGR even when `NO_COLOR` is set.
- **TEST-R3** `pixi run rs-ci` = `cargo fmt --check` + `cargo clippy --workspace --all-targets -- -D warnings` + `cargo test --workspace` (since M22: `pixi run rs-test`, the same tests under nextest, TEST-R10). Must pass before every commit.
- **TEST-R5** Allocation guarantees (CORE-R28, CORE-R29, CORE-R36, GEN-R11) are verified by counting heap operations on the current thread with `sciart_testalloc::CountingAlloc` (ADR-0009). Each such test file is its own integration-test binary declaring `#[global_allocator]`. `sciart-testalloc` is `publish = false`, only ever a dev-dependency, the only crate allowed `unsafe` (a single `#[allow(unsafe_code)]` on `impl GlobalAlloc`), and mirrors `[workspace.lints]` except `unsafe_code = "deny"` (enforced by its `tests/lints_mirror.rs`).
- **TEST-R4** Proptest case counts are kept modest (≤ 64 via `ProptestConfig::with_cases`) in `sciart-generators` and `sciart` so `rs-test` stays < 60 s; cheap pure properties in `sciart-core` may use proptest's default (256). `PROPTEST_CASES` can raise counts locally.
- **TEST-R6** (M11) `sciart-testalloc` also tracks live heap bytes on the current thread: `live_bytes()` is bytes allocated minus bytes freed, with a `realloc` counted as its size delta; a failed (null) allocation or `realloc` changes nothing. `crates/sciart-generators/tests/leak_free.rs` (its own test binary, TEST-R5) drives every registered scene through `Stage`: build at 80×24, then ten cycles of resizing 80×24 → 200×50 → 1×1 → 80×24, with 30 steps of 1/60 s and one render at each size. Live bytes after each of cycles 3..10 equal live bytes after cycle 2, so slow amortised growth (one small element per cycle) must cross a capacity doubling and show. The first two cycles are warm-up: they settle every buffer's largest capacity, including both halves of a double buffer swapped by `grid::regrid_*` (an odd number of regrids per cycle alternates their roles). Any difference is a leak or unbounded growth.
- **TEST-R7** (M11) For every scene, the live bytes held after building it through `Stage` at 500×150 (canvases included), stepping 1 simulated second and rendering once, measured from just before the build, stay under their ceiling in `leak_free.rs`: `LIVE_CEILING` = 2.75 MiB since M22 (4 MiB before; every scene pays ≈ 1.43 MB for the Stage's two canvases and a braille raster before its own state, and every scene not listed holds ≤ 2.51 MiB), or the scene's own entry in `EXCEPTIONS`, set at its M22 measurement plus ≈ 8 %, rounded up to 1/8 MiB and never above the old 4 MiB. M22 exceptions (measurement → ceiling, reason): fractal_growth 3.87 → 4 MiB, DLA lattice with its site list and melting queue reserved to the lattice cap so `update` never allocates (ADR-0012, GEN-R11); strange_attractors 3.81 → 4, per-dot f32 afterglow density; solar_surface 3.79 → 4, per-pixel disc and rim tables plus the half-block raster; rayleigh_benard 3.76 → 4, per-dot f32 stipple thresholds; snowflake_growth 3.74 → 4, hexagonal lattice fields in f64; aurora 3.68 → 4, per-pixel curtain layers and glow; star_trails 3.59 → 4, per-dot exposure and rank plus per-pixel sky levels; cloud_chamber 3.56 → 3.875, droplet slots reserved for allocation-free updates; heart_fibrillation 3.52 → 3.875, excitable lattice (u, v, slope, age); quantum_double_slit 3.32 → 3.625, complex wavefunction and ADI factors; binary_inspiral 3.32 → 3.625, precomputed field-dot table; kelvin_helmholtz 3.09 → 3.375, vorticity and dye lattices; noctilucent_clouds 2.93 → 3.25, wave-lattice nodes with packet phases; ising_model 2.89 → 3.125, spin lattice and display ages; gray_scott 2.73 → 3.0, double-buffered u/v lattices. M22 also dropped the doubling slack of buffers built once per resize (noctilucent_clouds −0.95 MiB, binary_inspiral −0.63, light_echo −0.27, saturn_rings −0.23, solar_surface −0.14, star_trails −0.11, jupiter_storms −0.09, chladni_plate −0.04), frames unchanged. Ceilings target ≤ 8 MiB and may only be lowered; raising one or adding an exception needs a spec change that names the scene and the reason here. Before M22, exceptions: none (M12: `galaxy_collision`, which held 6.24 MiB with blurred working copies of its exposures under a 7 MiB exception, now splats pre-blurred light straight into its four exposures, the box blur being linear, and holds ≈ 3.95 MiB). fractal_growth held 14.5 MiB in M11 until M12 capped its DLA lattice (ADR-0012). A per-scene exception keeps one outlier from loosening the guard for every other scene.
- **TEST-R8** (M11) `clippy.toml` `disallowed-methods` bans `std::boxed::Box::leak`, `std::vec::Vec::leak`, `std::string::String::leak`, `std::mem::forget` and `std::mem::ManuallyDrop::new` workspace-wide, so memory cannot be leaked on purpose; a source-rules test asserts every entry, as GEN-R7's test does for the clock bans. Code that truly needs one uses `#[allow(clippy::disallowed_methods)]` with a reason (none today).
